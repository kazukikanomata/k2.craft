# 記事の概要(description)を書く

記事の`description`は、次の3か所に表示される。

- 記事一覧・関連記事のカード
- 記事ページのヘッダー(タイトルと日付の下)
- `<meta name="description">`と、SNS共有時の説明文

読者が「この記事に何が書いてあるか」を一目で判断するための文章で、本文の冒頭のコピーではない。

## 制約

- **120文字以内**(`app/src/content.config.ts`のスキーマで検証され、超えるとビルドが失敗する)。目安は50〜90文字
- frontmatterの`description:`の1行だけを書き換える。他の行や本文は触らない
- 値はYAMLのダブルクォート文字列で書く。文中に`"`や`\`を入れない(入れるならエスケープする)

## 手順

1. **材料を集める**: リポジトリのルートで、対象記事のidを指定して実行する(idは`app/src/content/blog/<id>.md`のファイル名)。

   ```bash
   node .claude/skills/summarize-article/scripts/outline.mjs <id> [<id>...]
   node .claude/skills/summarize-article/scripts/outline.mjs --all   # 全記事
   ```

   タイトル・現在のdescription・見出し一覧・本文の冒頭と結びが出る。**これだけでは足りない記事は本文を直接読む**(見出しがない記事、感想・体験談の記事、冒頭が定型句だけの記事など)。

2. **書く**: 下の「書き方」に従う。

3. **反映する**: 各記事の`description:`行を書き換える。

4. **検証する**: `cd app && pnpm build`が通ることを確認する(文字数超過はここで検出される)。

5. **依頼者に確認を促す**: 全文を読んでいない記事は細部がずれている可能性がある。判断に迷った記事(内容が薄い記事、感想の結論を要約した記事など)を挙げて確認してもらう。

## 書き方

- 「何についての記事か」＋「何が分かる・何を書いたか」を1〜2文で書く。文末は「〜を紹介する」「〜をまとめた」「〜を解説する」「〜を振り返る」のように言い切る(です・ます調にしない)
- 記事に書かれていないことを足さない。推測で補わない
- 固有名詞は記事のものをそのまま使う。書籍・映画の題名は『』で囲む
- シリーズものは「第N回」「vol.N」を入れ、前後の回と区別できるようにする
- 感想・体験談は、書き手の結論や主張を要約する。書き手が言っていない評価を作らない
- ネタバレを含む記事は、その旨を書く
- 内容が薄い記事(ほぼ空の記事など)は、実際の中身に合わせて「短いメモ」などと正直に書く
- 避けるもの: 「はじめに」などの見出し・定型句の引用、本文の冒頭のコピー、アフィリエイトのリンク文言、URL、「〜について解説します」だけで中身が分からない書き方

## 例

| 記事 | description |
| --- | --- |
| CI/CDパイプライン | CI/CD(継続的インテグレーション/デリバリー)とは何か、なぜ便利かを整理し、Jenkins・CircleCI・Heroku CIといったツールを紹介する。 |
| 【AWS初学者】Lambda入門 | AWS Lambdaの入門。サーバーレスの考え方とランタイム・レイヤーなどの用語、ウォームスタートとコールドスタートを解説する。 |
| 【初学者向け】オブジェクト指向をJavaで理解する vol.2 | Javaでオブジェクト指向を学ぶシリーズの第2回。オーバーロード、コンストラクタ、staticの使い方をコード例で解説する。 |
| 映画『流浪の月』の感想 | 映画『流浪の月』の感想(ネタバレあり)。あらすじと印象に残った点を振り返り、「人は見たいようにしか見てくれない」というテーマを考える。 |
| Laravel forge deploy × AWS ver.4 | Laravel Forge×AWSの第4回。DNS(ドメインとIPアドレスを結びつける仕組み)を一言でまとめた短いメモ。 |
